1.10.1　一条贯穿全卷的主线

AI 的历史不是方法的堆积，而是一条清晰的主线：用越来越少的先验，换越来越大的数据和算力。

  • 符号主义时代：人把规则写进去，机器只做推理；
  • 统计学习时代：人设计特征，机器学权重；
  • 深度学习时代：机器学特征，人设计结构；
  • 大模型时代：机器学结构的一部分，人只设计训练目标与数据配比。

每往右走一步，人工先验减少，对数据和算力的依赖增加。这也解释了为什么"AI 落地"在不同行业难度差异巨大：数据充足、反馈快的领域（搜索、推荐、语音、视觉）先被吃掉；数据稀缺、错误代价高的领域（医疗诊断、工业控制）走得最慢。

1.30.3　几个贯穿全卷的判断

这些结论在后面的章节会反复出现，先摆出来：

  1. 先有基线，再谈模型。 任何任务的第一步都是一个能在一天内跑通的最简方案（逻辑回归、LightGBM、或一个预训练模型的零样本调用）。没有基线的"提升"无法证明。
  2. 指标先于模型。 指标定义错了，模型越好越糟。离线指标与线上目标不一致，是所有 AI 项目最常见的死法。
  3. 数据决定上限，模型决定离上限多近。 数据噪声、标签不一致、分布偏移，这些问题的模型侧努力基本无效。
  4. 复杂度要和收益匹配。 从 92% 到 93% 的准确率，可能要多付 20 倍推理成本。这笔账必须提前算。
  5. 能被监控的才叫上线。 没有输入分布监控、没有回滚机制、没有错误样本回流，系统迟早会静默失效。

1　六十年：三次浪潮与两次寒冬

三次浪潮与两次寒冬，以及每一轮"AI 要取代人"的预言为什么都没按时兑现。

全景　·　约 1124 字　·　3 分钟

了解历史不是为了背年份，而是为了看清一件事：这个领域每隔十几年就会重演一次"能力被高估、然后被现实打回"的循环。知道这个模式，你对当下任何"颠覆性突破"的判断都会更冷静。

时期主线代表成果为什么会结束
1943–1956神经元模型与图灵测试McCulloch-Pitts 神经元、感知机单层感知机无法解决异或，被证明能力有限
1956–1974符号主义与搜索通用问题求解器、LISP组合爆炸、常识难以手工编码
1974–1980第一次寒冬经费收缩承诺与现实差距过大
1980–1987专家系统医疗诊断、配置系统规则维护成本爆炸，无法处理不确定性
1987–1993第二次寒冬—专家系统泡沫破裂
1986–2011统计学习反向传播、SVM、随机森林、CRF特征工程瓶颈、数据规模受限
2012–2017深度学习AlexNet、ResNet、seq2seq、GAN需要大量标注，泛化到新任务成本高
2017–2022预训练 + 微调Transformer、BERT、GPT每任务一模型，部署与维护成本高
2022–至今大模型与多模态指令微调、RLHF、扩散、Agent推理成本、可靠性、幻觉仍未解决

2.11.1　三次浪潮共同的形状

每一轮都遵循同一个剧本：

  1. 一个新方法解决了旧方法的瓶颈（感知机解决手工规则，深度学习解决特征工程，大模型解决任务定制）；
  2. 媒体与资本把"能做什么"外推成"什么都能做"；
  3. 真实场景的边界条件（数据、成本、可靠性）暴露；
  4. 进入低谷，但方法本身沉淀下来。

低谷期并非浪费：SVM、集成学习、概率图模型都是在寒冬前后成熟的，它们至今是表格数据与可解释场景的主力。

2.21.2　两次真正的转折点

如果只能记两个节点，记这两个：

  • 2012 年 AlexNet：GPU + ReLU + Dropout + 大数据，把 ImageNet 错误率从 26% 拉到 15%。它证明的不是"卷积好用"（卷积早就好用），而是"算力 + 数据"能突破手工特征的天花板；
  • 2017 年 Transformer：把序列建模从串行改成并行，使"堆更多层、喂更多数据"在工程上可行。它之后的每一年，模型规模与数据规模都在按同一条曲线增长。

2.31.3　当前阶段的三个真实约束

历史告诉我们，判断一个技术能否落地，看三件事是否同时成立：

约束现状影响
数据文本、图像充裕；专业领域稀缺通用能力易得，专业能力仍需标注
算力训练集中在大厂，推理可下沉本地部署以量化为前提
可靠性幻觉、分布外失效仍普遍高风险场景必须人在回路

结论：通用能力已经"过剩"，稀缺的是可靠性与领域数据。 这也是为什么近几年的技术热点集中在 RAG、Agent、评测、对齐——它们都在补"可靠性"这一块。

要点

看到"某模型又突破"时，先问三个问题：它在什么数据上评的？失败模式是什么？单位成本多少？这三问能过滤掉大部分噪音。

2　机器学习方法论：先把问题定对

项目失败最多的地方不是模型，而是"要预测什么""怎么算对""怎么验证"这三件事没想清楚。

方法论　·　约 2042 字　·　5 分钟

一个 AI 项目的成败，在写第一行代码之前就决定了大概七成。这一章讲的都是"动手之前"的事。

3.12.1　先分清任务类型

任务有标签典型问题常用方法
监督·分类是（离散）欺诈、故障、意图识别逻辑回归、树集成、神经网络
监督·回归是（连续）销量、价格、剩余寿命线性、GBDT、神经网络
排序是（相关性等级）搜索、推荐LambdaMART、双塔、交叉特征
无监督否分群、异常检测、降维K-means、孤立森林、PCA
自监督无（自己造）表示学习、预训练掩码、对比学习
强化学习奖励控制、调度、游戏PPO、DQN、策略搜索

最容易搞错的是"分类 vs 排序"。推荐系统里"用户会不会点"是分类，但产品要的是"给这个用户排哪十个"，两者目标函数不同。把排序当分类训，模型会倾向于推"人人都点"的热门内容，个性化反而变差。

3.22.2　指标：选错了会把人带偏

二分类的混淆矩阵给出四个数：TP、FP、FN、TN。由此派生：

\text{Precision}=\frac{TP}{TP+FP},\qquad \text{Recall}=\frac{TP}{TP+FN},\qquad F_1=\frac{2PR}{P+R}

解释一遍：

  • 精确率：报出来的有多少是真的（错了会怎样）；
  • 召回率：真的里面抓到了多少（漏了会怎样）；
  • F_1：两者的调和平均，偏向较小的一方。

还有两个"阈值无关"的指标：

  • ROC-AUC：随机取一个正样本和一个负样本，正样本得分高于负样本的概率。它在类别平衡时很好用；
  • PR-AUC：在类别极不平衡（比如欺诈只占 0.1%）时更可靠，因为 ROC 的假阳性率分母是 FP+TN，负样本极多时 ROC 会显得很好看，而实际精确率很低。
常见坑
  • 类别不平衡时只看准确率：99% 的样本是负类，一个"全预测负类"的模型准确率 99%，毫无用处。
  • 只看 AUC 不看阈值：AUC 0.9 的模型，在业务要求的精确率下召回可能只有 10%。必须画出 PR 曲线，选工作点。
  • 回归任务只看 RMSE 不看分布：RMSE 会被少数大误差主导，如果业务关心"大多数情况"，MAE 更合适；如果关心"极端情况别太离谱"，看 P95 分位误差。

3.32.3　数据划分：验证集是怎么被污染的

标准做法是训练集 / 验证集 / 测试集，比例常见 6:2:2 或 8:1:1。三条铁律：

  1. 测试集只能用一次。反复看测试集调参，等于把它变成了验证集，最终指标会虚高；
  2. 时间序列必须按时间切。用未来预测过去，或者随机打乱时间顺序，会造成信息泄漏——模型在训练时"见过未来"；
  3. 分组不能跨集合。同一个用户、同一张图的不同裁剪、同一病人的多次检查，必须整体落在同一个集合里，否则验证分数没有意义。

交叉验证（k-fold）用于数据量小的情况：把数据分 k 份，轮流用一份做验证。它给出的是"性能的方差估计"，而不只是一个数——方差大说明模型对数据划分敏感，这本身就是信息。

过拟合实验台同一批数据，把多项式次数从 1 拉到 9，看训练误差与泛化

3.42.4　偏差与方差：一条曲线解释一切

把期望泛化误差分解：

\mathbb{E}\big[(y-\hat f(x))^2\big]=\underbrace{\text{Bias}^2}_{\text{模型太简单}}+\underbrace{\text{Variance}}_{\text{模型太敏感}}+\underbrace{\sigma^2}_{\text{噪声下界}}
  • 高偏差：训练误差和验证误差都高，模型欠拟合；
  • 高方差：训练误差低、验证误差高，模型记住了噪声；
  • \sigma^2 是数据本身的不可约误差，换模型也消不掉。

这个分解的价值在于它把"调参"变成了诊断：先看训练/验证误差的差距，判断你在曲线的哪一侧，再决定是加容量还是加正则。上面的实验台可以直接看到这条曲线：次数从 1 增到 9，训练误差一路降，泛化能力先降后升。

3.52.5　类别不平衡的四种处理

手段做法代价
重采样过采样少数类 / 欠采样多数类过采样易过拟合，欠采样丢信息
加权损失少数类损失乘大权重权重过大会导致校准变差
阈值调整不改训练，只调判定阈值最简单，最常被忽略
合成样本SMOTE 在少数类近邻间插值高维或类别边界复杂时效果差

优先级建议：先调阈值，再考虑加权，最后才重采样。 阈值调整不改变模型，只改工作点，代价最低。

3.62.6　把问题定清楚的五个问题

动手前，逐个回答：

  1. 预测目标是什么？ 一个具体的、可观测的量（"7 天内是否流失"），而不是抽象概念（"用户满意度"）。
  2. 标签怎么来？ 人工标注、日志回填、还是业务结果？延迟多久？有没有系统性偏差？
  3. 错误的代价对称吗？ 漏检一个欺诈 vs 误封一个正常用户，代价可能差百倍，这决定了指标与阈值。
  4. 上线后靠什么监控？ 输入分布、输出分布、业务指标，三者至少要监控两个。
  5. 最简基线是什么？ 规则、历史均值、热门推荐、零样本调用大模型——先有一个能对比的数。
工程视角

这五个问题写成文档，比任何模型架构图都重要。实践中最常见的返工是：模型训完才发现标签定义和业务口径不一致。标签定义要落到 SQL 或代码里，不要停留在自然语言描述。

3.7特征工程的实操清单

拿到一张表，按这个顺序过一遍，通常能拿到大部分收益：

步骤动作判断依据
1 看分布每列的缺失率、取值数、偏度缺失 > 30% 的列要么删要么单独建模
2 处理时间拆出年/月/日/星期/是否节假日有周期性的业务几乎必做
3 处理类别频次编码 + 目标编码（带折外防泄漏）高基数类别不要直接 one-hot
4 造交叉两两相乘、比值、差值业务上有关联的才做
5 聚合特征按用户/商品的统计量（均值、计数、最近一次）注意只能用当前时刻之前的数据
6 筛选重要性排序，去掉冗余相关性 > 0.95 的成对特征留一个

目标编码是最容易泄漏的一步：用全量数据算类别均值，等于把标签信息带进了特征。正确做法是 K 折外编码——每一折用其余折的数据算均值。

3.8交叉验证：什么时候不能用随机划分

数据结构划分方式原因
独立同分布样本随机 K 折常规
同一用户多条记录按用户分组否则同人数据同时出现在训练与验证
时间序列按时间切否则用到未来信息
同一文档多段按文档分组否则模型记住了文档而不是规律

判断方法很朴素：问一句"这条验证样本的信息，训练时能不能看到"。能看到，就必须换划分方式。

4.23.2　线性模型的价值：可解释与可校准

逻辑回归的系数 \beta_j 表示"特征 x_j 增加一单位，对数几率增加 \beta_j"。这是业务方唯一能直接读懂的形式，也是风控、医疗、金融等受监管行业仍大量使用它的原因。

两点工程经验：

  • 先做特征标准化，否则系数大小不可比（正则化也会失真）；
  • 注意多重共线性：两个高度相关的特征会让系数符号翻转，解释失真。用 VIF 检查，或改用岭回归。

4.33.3　树集成：表格数据的事实标准

LightGBM 在中等数据上通常是最强基线，配置建议：

python
import lightgbm as lgb

params = dict(
    objective='binary',
    learning_rate=0.05,        # 先小一点，配合更多轮
    num_leaves=31,             # 控制复杂度，别超过 2^depth
    min_data_in_leaf=20,       # 防过拟合的关键参数
    feature_fraction=0.8,      # 列采样，降相关性
    bagging_fraction=0.8,
    bagging_freq=1,
    lambda_l2=1.0,             # 叶权重正则
    metric='auc',
)
# 早停：验证集连续 50 轮不提升就停
model = lgb.train(params, dtrain, num_boost_round=2000,
                  valid_sets=[dvalid], callbacks=[lgb.early_stopping(50)])

调参优先级（按收益排序）：learning_rate + num_boost_round 一起调 → num_leaves / min_data_in_leaf → 采样比例 → 正则项。

不要做的事：把连续特征做标准化（树不在乎）、对缺失值做插补（LightGBM 原生处理更好）、做大量多项式特征（树自己会组合）。

4.43.4　核 SVM：小样本高维的可靠选择

适用条件很明确：样本量几千以内、特征维度高、边界非线性但类别可分。文本分类（TF-IDF 特征）是它的经典战场。

三个必调项：C（正则强度）、核类型、RBF 的 \gamma。经验起点：C 从 1 开始按 10 倍网格搜索，\gamma 取 1/d（d 是特征数）附近。

不适用的场合：样本超过 5 万（训练 O(N^3)）、需要输出概率（要用 Platt 校准，成本不低）、需要在线更新。

4.53.5　KNN 与朴素贝叶斯：简单但边界清晰

KNN 没有训练阶段，预测时算距离。它的隐含假设是"近处样本同类"。高维时距离会失效（维度灾难：所有点对的距离趋于相同），必须先降维或选特征。适合作为"必须极简"场景的兜底。

朴素贝叶斯 假设特征在给定类别下条件独立。这个假设几乎总是错的，但它在文本分类上仍然有效——因为分类只需要"哪个后验最大"，不需要概率精确。它的优点是训练是闭式解、极快、可增量。

4.63.6　可解释性：三种工具

工具说明适用
特征重要性（分裂增益）树模型自带，反映"用了多少"快速筛查，但有偏（偏好高基数特征）
Permutation importance打乱某特征看指标掉多少更可靠，计算成本高
SHAP基于博弈论的边际贡献分配单样本解释，可加性严格

SHAP 值得多用：它给出"这个样本为什么被判为高风险"的逐特征归因，业务方能接受，也便于发现数据 bug（比如某个 ID 类特征贡献异常高，往往是泄漏）。

工程视角

选型时算一笔账：一个 LightGBM 模型训练 3 分钟、推理 50 微秒、内存 100MB、可解释；一个 7B 模型推理 50 毫秒、需要 GPU、不可解释。同样 92% 的准确率，前者在多数业务里更划算。 先证明收益，再升级复杂度。

4　数据工程：模型的上限在这里

数据泄漏、标签噪声、分布偏移——三个让模型白训的问题，以及各自的检查方法。

数据　·　约 1504 字　·　4 分钟

有一句被反复引用的话：数据和特征决定了上限，模型只是逼近这个上限。这一章讲三件最容易做错的事。

5.14.1　数据泄漏：最常见的"高分离奇好"

泄漏指训练时用到了预测时拿不到的信息。它的表现是离线指标异常好，上线立刻崩。四种典型形态：

类型例子怎么发现
时间泄漏用未来的统计量做特征（如全量均值）特征与标签的相关性高得反常
目标泄漏特征里混入了标签的派生量（如"结案时间"）单特征 AUC 异常高
分组泄漏同一实体跨训练/验证集按实体分组重切后指标大跌
重复样本同一记录重复出现在两个集合去重后指标变化

排查方法很朴素，但有效：逐个特征算单特征 AUC，凡是超过 0.9 的都去看一眼它的定义。真正有强预测力的特征很少，异常高的往往是泄漏。

5.24.2　标签质量：噪声从哪来

标签不是真理，是观测。三类常见问题：

  • 标注不一致：同一批数据两个人标出不同结果。先算标注者间的一致率（Cohen's \kappa），低于 0.6 说明定义本身模糊，要先修定义；
  • 代理标签偏差：用"点击"当"喜欢"，用"复购"当"满意"。代理与目标的相关性决定了模型上限；
  • 延迟标签：欺诈要 30 天后才确认，模型只能用 30 天前的数据训练。这会引入"标签未成熟"问题，需要设置观察窗口。

处理噪声的实用手段：对称损失（对噪声鲁棒）、置信学习（用模型找出高概率错标的样本再人工复核）、多标注者投票。但优先级最高的是修流程，而不是修算法。

5.34.3　分布偏移：上线之后才暴露的问题

训练分布 p_{\text{train}}(x,y) 与线上 p_{\text{live}}(x,y) 不一致，模型就会退化。三种类型：

类型变化例子
协变量偏移只有 p(x) 变用户结构变化、季节变化
概念偏移p(y\mid x) 变欺诈手法升级、用户偏好变
标签偏移p(y) 变大促期间购买率暴涨

监控上分别对应：输入特征的分布监控（PSI、KS）、预测分布的监控、业务指标的监控。三者缺一不可，因为协变量偏移可以先于指标暴露出来。

5.44.4　特征工程的现代做法

深度模型能自动学特征，但"喂什么进去"仍然关键。三类手工特征仍有价值：

  • 统计聚合：用户近 7/30/90 天行为计数、金额均值——树的模型尤其吃这类特征；
  • 交叉特征：类别 × 类别的组合（如"城市 × 时段"），在推荐里效果显著；
  • 时间特征：星期、是否节假日、距上次行为的间隔。注意周期编码（sin/cos）比整数编码更合理，避免"周日 0 与周一 6 距离很远"的假象。
常见坑
  • 用全量数据算标准化参数再划分训练集——这是泄漏，标准化统计量必须只从训练集算；
  • 目标编码（target encoding）直接在全集上算均值——严重泄漏，必须在折内计算；
  • 把 ID 类高基数特征直接 one-hot——维度爆炸且学到噪声，应改用频次编码或 embedding。

5.54.5　数据量：够不够的判断

粗略的经验（会有偏差，但能给你量级感觉）：

任务从零训练微调预训练模型
图像分类（10 类）每类数千每类数十
文本分类数万条数百到数千
目标检测每类数千张数百张
语音识别数百小时数十小时

先问"能不能用预训练模型"，再问"要多少数据"——这一步经常能把需求降一到两个数量级。

5.6标注质量管理：四个必须做的动作

标注是 AI 项目里最贵也最容易被低估的一环。四条基本纪律：

  1. 先写规范，再招人。规范里要有正面例子与边界例子，不能只有定义；
  2. 双标注 + 一致性检验。抽 10% 做重复标注，算 Cohen's kappa；低于 0.6 说明规范本身有问题，不是标注员的问题；
  3. 黄金集。混入 20 条已确定答案的样本，定期检查标注员是否漂移；
  4. 回流机制。线上发现的错例，定期加入训练集，形成闭环。
指标含义健康值
标注一致性 kappa两人标注的吻合程度> 0.7
黄金集通过率标注员对已知答案的准确率> 95%
单条耗时标注效率与预算匹配

一个反直觉的结论：标注质量的上限由规范决定，不由标注员决定。规范模糊时，加人只会增加噪声。

5　深度学习：一条能重复的训练流水线

一条训练流水线怎么搭，超参按什么顺序调，以及九种失败模式的对症表。

深度学习　·　约 1422 字　·　4 分钟

原理部分（初始化、归一化、残差）在卷一第 10 章讲过。这一章讲操作层：怎么组织代码、按什么顺序调参、出了问题怎么定位。

6.15.1 训练循环的心智模型

任何训练脚本都是这五步的循环：

python
for step, batch in enumerate(loader):
    x, y = batch                       # 1. 取数据（含增强、设备拷贝）
    logits = model(x)                  # 2. 前向
    loss = criterion(logits, y)        # 3. 损失
    loss.backward()                    # 4. 反向（建图 -> 回传）
    optimizer.step()                   # 5. 更新
    optimizer.zero_grad(set_to_none=True)  # 清梯度，放最后更省内存

把这五步写成可开关的开关，是让调试变快的关键：能在 100 个样本上跑完整个循环、能关掉增强、能只跑前向。很多"训不动"的问题，靠缩小规模能在十分钟内定位。

6.25.2 超参的调整顺序

按影响大小排（而不是按论文里写得多的排）：

  1. 学习率：影响最大。先用 lr range test 扫一遍，选损失下降最快的区间的下限；
  2. batch 大小与调度：batch 大则 lr 要相应放大（线性缩放规则），并配 warmup；
  3. 模型规模：宽/深按数据量选，宁可先小后大；
  4. 正则强度：weight decay、dropout、label smoothing，先只调 weight decay；
  5. 其余：优化器细节（\beta_1,\beta_2,\epsilon）、增强强度。

一个常被忽略的事实：小模型 + 好数据 > 大模型 + 一般数据。在数据有限时，先把数据质量提上去，收益通常超过换模型。

6.35.3 迁移学习：三种微调策略

策略做法适用
冻结主干只训最后的分类头数据极少（数百）、任务与预训练接近
分层学习率主干 lr 小、头部 lr 大中等数据、任务有差异
全量微调所有参数更新数据充足、任务差异大

视觉任务的经验起点：冻结主干训 5 轮头部，再解冻全部用 1/10 的学习率微调。文本任务用 BERT 类模型时，学习率 2e-5 到 5e-5 是常见区间，太大容易破坏预训练知识。

6.45.4 显存：先算清楚再看 OOM 报错

训练显存大致由四部分组成：

\text{总显存}\approx \underbrace{\text{参数}}_{\text{权重}}+\underbrace{\text{梯度}}_{\text{同权重}}+\underbrace{\text{优化器状态}}_{\text{Adam 约 2 倍权重}}+\underbrace{\text{激活值}}_{\text{与 batch、序列长成正比}}

以 FP16 + Adam 训练 7B 模型为例：权重 14GB、梯度 14GB、Adam 的 m 与 v 各 28GB（FP32）、激活另算——光静态部分就超过 80GB。这解释了为什么需要 ZeRO/FSDP 做参数分片（卷三展开）。

常见省显存手段的优先级：小 batch + 梯度累积 → 混合精度 → 梯度检查点 → 参数分片。

6.55.5 九种失败模式对症表

训练降验证升过拟合加正则、加数据、减容量

工程视角

把训练脚本做成可断点续训、可精确复现（固定种子 + 记录版本）、日志结构化（loss、lr、梯度范数、吞吐）。这三件事在第一次跑长训练时看起来是浪费时间，在第二次改模型时会救你。

6　计算机视觉：四个任务，四种评价

分类、检测、分割、深度估计：四个任务的评价方式完全不同，选型逻辑也不同。

视觉　·　约 1563 字　·　4 分钟

你有数字图像处理的底子，这一章的重点不是"卷积是什么"，而是任务怎么定义、指标怎么算、方案怎么选。

7.16.1 分类：从单标签到多标签

分类的输出是一个概率向量。三个现代要点：

  • 数据增强是主要收益来源：RandAugment、MixUp、CutMix 这类方法在中小数据集上能提升几个点，比换模型划算；
  • 标签平滑抑制过度自信，改善校准；
  • 长尾问题：真实数据类别极不均衡，用重采样、logit adjustment 或两阶段训练（先均衡预训练，再长尾微调）。

指标：Top-1 / Top-5 准确率。注意类别不均衡时用宏平均（macro-F1），不要用微平均，后者会被大类主导。

7.26.2 检测：框的匹配与 NMS

检测输出"每个目标的框 + 类别"。核心机制有三个：

  1. 锚框 / 无锚：Faster R-CNN 用锚框，YOLO 后期版本用中心点 + 尺寸回归，省掉锚框调参；
  2. IoU 与匹配：预测框与真值框的交并比决定"算不算命中"。IoU 阈值 0.5 常用于"是否检出"，0.75 用于"框得准不准"；
  3. NMS：同一目标会有多个重叠框，按分数排序后抑制 IoU 超过阈值的。

指标是 mAP（各类 AP 的均值），分 mAP@0.5 和 mAP@0.5:0.95（后者对框的精度要求更高）。报告 mAP 时必须写清阈值，否则数字不可比。

常见坑
  • 小目标检测：下采样太多导致小目标在特征图上只剩几个像素。解法是高分辨率特征图、FPN 多尺度融合、切片推理（把大图切块分别检测再合并）；
  • NMS 阈值调不好会"吞掉"密集目标（人群、货架），改用 Soft-NMS 或可学习的 NMS。

7.36.3 分割：像素级的三类任务

类型输出代表方法指标
语义分割每像素类别U-Net、DeepLabmIoU
实例分割每实例的掩码Mask R-CNNmask mAP
全景分割两者合并Panoptic FPNPQ

mIoU 的定义是"交并比在所有类别上取平均"，它惩罚"漏标"和"多标"同样重。医学图像里更常用 Dice 系数，因为它对类别极不平衡更友好。

现代趋势是提示式分割（SAM 一类）：给定点、框或文本提示，输出掩码。它把分割从"每类训一个模型"变成"一个模型适配多任务"，这大幅降低了标注需求。

7.46.4 从图像处理到深度视觉：哪些东西没变

你在图像处理课上学的东西依然有效，只是角色变了：

传统技术在深度视觉里的位置
高斯滤波 / 双边滤波预处理去噪；也可作为固定卷积核嵌入网络
边缘检测（Sobel/Canny）浅层卷积学到的正是这类核；Canny 仍用于后处理与标注辅助
形态学操作掩码后处理（去除小连通域、填补空洞）
直方图均衡 / Gamma数据增强与预处理；但要注意它会改变分布
多尺度金字塔FPN、图像金字塔推理，思想完全相同
光流视频理解的基础；传统 Lucas-Kanade 仍用于快速场景

一句话：传统方法是可解释的先验，深度方法是可学习的先验。 二者常常组合使用，而不是替代关系。

7.56.5 部署侧的现实约束

视觉模型上线的瓶颈很少是精度，而是：

  • 延迟：1080p 视频 30fps 意味着每帧 33ms 的预算，包含解码、预处理、推理、后处理；
  • 量化：INT8 量化通常带来 2–4 倍加速，精度掉 0.5–2 个点，需要逐层校准；
  • 输入分辨率：分辨率翻倍，卷积计算量翻 4 倍。很多"精度提升"其实来自更高分辨率，而不是更好的结构；
  • 算子支持：某些自定义算子（如可变形卷积）在目标推理引擎上不支持，会被回退到 CPU，性能骤降。
工程视角

选型时先定延迟预算，再选模型。一个能在 20ms 内跑完的 85% mAP 模型，胜过一个需要 80ms 的 88% mAP 模型——因为前者能上更多路摄像头，总覆盖收益更高。这是工程判断，不是精度竞赛。

7.6上线前的精度检查清单

离线 mAP 高不等于线上可用。上线前必查五项：

检查做法常见问题
分布一致性对比线上与训练集的亮度、分辨率、长宽比分布线上手机拍摄的畸变与训练集不符
小目标单独统计小尺寸目标的召回整体 mAP 掩盖了小目标崩塌
类别不均衡看每类的 P/R，不只看均值稀有类几乎检不出
后处理参数NMS 阈值、置信度阈值在线上数据上重调沿用训练集的最优值
延迟端到端测（含解码、后处理）只测了模型前向

最容易被忽略的是第四项：置信度阈值直接决定"误检 vs 漏检"的平衡，而它应该由业务代价决定，不是由验证集 F1 决定。

7　自然语言处理：从词表到检索

从分词到检索：NLP 的每个环节都有它的坑，指标尤其不可信。

自然语言　·　约 1516 字　·　4 分钟

文本任务的难点不在模型结构，而在离散符号如何变成连续向量、以及评价指标如何逼近人的判断。这两件事至今没有完美解法。

8.17.1 分词：第一个不可回避的选择

模型不认识字符串，只认识 ID。分词（tokenization）把文本切成子词单元。三种主流算法：

算法做法特点
BPE从字符开始，反复合并最高频相邻对GPT 系使用，压缩率好
WordPiece合并能最大化似然增益的对BERT 系使用
Unigram从大词表开始，按损失删减SentencePiece 常用，多语言友好

中文的特殊性：没有空格，所以早期用字级或词级（依赖分词工具），现在主流是直接在字/子词级别做 BPE，让模型自己学组合。

一个常被忽略的事实：词表大小是一个工程权衡。词表大 → 序列短（推理快）、但嵌入矩阵大、低频词学不好；词表小 → 序列长（推理慢）、但泛化好。LLaMA 系用 32K，一些多语言模型用 100K 以上。

8.27.2 词向量：从静态到上下文相关

  • 静态词向量（word2vec、GloVe）：一个词一个向量。问题是多义词无法区分（"苹果"既是水果也是公司）；
  • 上下文词向量（ELMo、BERT）：同一个词在不同句子里得到不同向量。这是预训练模型的根本贡献。

word2vec 的训练目标（skip-gram + 负采样）在卷一第 14 章推导过，其思想——"把正样本与随机负样本分开"——是对比学习的原型。

8.37.3 四类任务与各自的评价

任务输入→输出指标指标的坑
文本分类文本→标签准确率、宏 F1类别不均衡时必须看每类
序列标注（NER）文本→每 token 标签实体级 F1必须按实体算，不能按 token 算
抽取式问答问题+段落→片段EM / F1EM 要求完全匹配，过于严格
生成（翻译/摘要）文本→文本BLEU / ROUGE / BERTScore与人的判断相关性弱

BLEU/ROUGE 的局限值得单独强调：它们基于 n-gram 重叠，对同义改写、语序变化极不敏感。一个语义完全正确但用词不同的译文可能得分很低。所以现在的生成任务更常用：

  • BERTScore：用上下文嵌入算相似度，对改写更宽容；
  • COMET / BLEURT：训练过的评估模型；
  • LLM-as-judge：用强模型按标准打分，成本高但更接近人。

8.47.4 检索：最被低估的一环

很多"大模型答不准"的问题，根源在检索而不是生成。检索的基本流程：

  1. 切分（chunking）：把文档切成 200–500 字的块，重叠 10–20% 避免切断语义；
  2. 编码：用双塔模型（如 bge、e5 系列）把块编码成向量，离线建索引；
  3. 召回：向量近邻（HNSW/IVF）+ 关键词（BM25）双路召回；
  4. 重排（rerank）：用交叉编码器对 Top-50 精排，取 Top-5。

双塔与交叉编码器的区别很重要：

  • 双塔：query 与 doc 分别编码，可离线建索引，快，但交互信息少；
  • 交叉编码器：把 query 与 doc 拼起来一起编码，精度高，但每个候选都要过一次模型，只能用于重排。

先用双塔召回 50 个，再用交叉编码器重排，这是成本与效果的平衡点。卷三会展开完整链路。

常见坑
  • 只用向量检索：专有名词、编号、代码这类"精确匹配"需求会漏，必须加 BM25；
  • chunk 太大：召回的是长段落，生成时上下文被稀释；太小则语义不完整；
  • 用通用嵌入模型做垂直领域检索：金融、医疗、法律的术语分布差异大，需要在领域数据上微调嵌入模型。

8.57.5 传统方法与预训练模型的分界

场景建议
有标注数据几千条以上微调预训练模型（BERT 类），通常最优
标注极少（几十条）零样本/少样本提示，或先用 LLM 生成弱标签

"LLM 全能"是个误解：在固定类别的分类任务上，一个小 BERT 微调后往往比调用大模型更准、更快、更便宜。大模型的优势在开放域、少样本、需要推理与生成的场景。

8　大模型：能力边界与成本结构

大模型能做什么、不能做什么、贵在哪——三个问题的答案决定了它在你的项目里该放在什么位置。

大模型　·　约 1383 字　·　4 分钟

这一章不讲解法（解法在卷三），讲判断：什么时候该用大模型、用多大的、贵在哪、承诺给业务方的能力里哪些是靠不住的。

9.18.1 三段式训练范式

阶段数据目标得到什么
预训练万亿级 token 文本下一个 token 预测语言能力、世界知识、推理雏形
监督微调（SFT）数万到数百万条指令-回答学会"按指令作答"可用性、格式遵循
对齐（RLHF/DPO）人类偏好对比让回答更符合偏好有用性、无害性、语气

这个范式解释了一个常见困惑：为什么模型"知道"很多却常常答错？因为预训练优化的是"预测下一个词"，而不是"说真话"。知识以统计关联的形式存在，不是可检索的事实库。SFT 与对齐改变的是行为风格，不能保证事实正确。

9.28.2 能力边界：四类可靠与四类不可靠

相对可靠相对不可靠
语言改写、翻译、摘要精确数值计算、多步算术
格式转换、结构化抽取长链逻辑推理（超过 5–6 步）
代码生成（有明确模式）需要外部实时信息的事实问答
按给定材料作答判断"自己不知道"（校准差）

第三行与第四行是最需要工程补偿的：前者靠工具调用（计算器、代码执行），后者靠检索与"引用出处"约束。

关于幻觉，需要理解它的机制而不是当成 bug：模型在生成每个 token 时做的是概率采样，流畅性与正确性由同一个目标驱动。当训练数据里"看起来合理的错误"很常见时，模型会学到"编得像"比"承认不知道"更符合分布。所以要靠外部约束（检索、引用、拒答训练），不能靠提示词根治。

9.38.3 成本结构：三笔账

训练账

\text{训练算力}\approx 6\times N\times D

N 是参数量，D 是训练 token 数。这个 6 来自前向 2 次 + 反向 4 次浮点运算/参数/token。例如 7B 模型训 2T token：6\times7\times10^9\times2\times10^{12}\approx8.4\times10^{22} FLOPs。按 A100 的 312 TFLOPS（FP16，实际利用率约 40%）折算，需要约 6.7\times10^{5} GPU 小时。

推理账

\text{每 token 算力}\approx 2N\ (\text{前向}),\qquad \text{显存}\approx \text{权重}+ \text{KV cache}

7B 模型 FP16 权重 14GB，加上 KV cache 与激活，单卡 24GB 可以跑；13B 需要 24GB 以上或量化；70B 需要多卡或 INT4。

上下文账

上下文长度不是免费的：KV cache 随序列长度线性增长，注意力计算随长度平方增长。长上下文 = 更贵的显存 + 更慢的首 token。这是"为什么不能无脑塞满上下文"的量化解释。

9.48.4 选型：参数规模与任务匹配

任务建议规模理由
分类、抽取、改写（有标注）小模型微调（0.1–1B）或 BERT 类精度足够、成本低一个量级
通用问答、RAG7–14B能力与成本平衡点
复杂推理、代码30B 以上或调用 API规模对推理能力影响显著
端侧/离线1–4B 量化内存与功耗约束
高并发简单任务API 或小模型 + 缓存单位成本优先

一个务实策略：先用最大的可用模型做"能力上限测试"，再用小模型逼近。如果大模型也做不好，说明问题不在模型规模，而在任务定义或数据。

9.58.5 评测的陷阱

  • 数据污染：benchmark 的题目可能出现在预训练语料里，分数虚高；
  • 提示敏感：同一个模型换一种问法，分数差 10 个点；
  • 选择偏差：只报告最好的那次运行；
  • 指标与用途脱节：MMLU 高不代表你的业务场景好。

靠谱的做法是自建业务评测集：从真实流量里采样 200–500 条，人工标注期望输出，形成回归测试。这个集合比任何公开榜单都有用。

要点

把大模型当"能力很强但不可靠的实习生"来用：给它明确的材料（检索）、明确的格式（结构化输出）、明确的检查（后处理校验），并保留人工复核。这个定位比"智能助手"更符合它现在的实际水平。

10.19.1 图像生成：可控性比质量更重要

文生图的基本架构是"文本编码器 + 扩散主干 + 解码器"。稳定扩散系列还多一个 VAE，把 512×512 的图压到 64×64 的潜空间再扩散，算力省几十倍。

真正决定可用性的是控制手段：

手段作用代价
提示词描述内容与风格不稳定，对措辞敏感
负向提示排除不要的元素需要经验

要点

"生成质量"很快会同质化，"可控与可编辑"才是产品差异点。做图像产品时，把预算投在控制链路上，比投在换更大的基座模型回报更高。

10.29.2 视频生成：一致性问题

视频比图像多了时间维，难点从"像不像"变成"动不动得对"：

  • 时序一致性：人物的脸、衣服纹理、光照在帧间不能跳变；
  • 运动合理性：物理规律（重力、碰撞）与镜头运动；
  • 长视频：自回归拼接容易漂移，需要关键帧锚定。

当前主流做法是潜空间扩散 + 时空注意力（把时间当第三维做注意力），或者用"图像模型 + 运动模块"分离训练。评测仍不成熟，常用人工打分与光流一致性。

10.39.3 语音：三个独立任务

任务输入→输出主流方案关键指标
ASR（识别）音频→文本Conformer / Whisper 类字错率 CER
TTS（合成）文本→音频扩散/流匹配声码器MOS 主观分、RTF
声纹/分离音频→身份/干净音轨说话人嵌入、源分离等错误率 EER、SI-SDR

语音的特殊约束是实时性：流式 ASR 要求"边说边出字"，延迟控制在几百毫秒，这与非流式模型的精度有取舍（看未来上下文 vs 只看历史）。

10.49.4 多模态：CLIP 是分水岭

CLIP 用对比学习把图像与文本对齐到同一个向量空间：一批图文对里，配对的为正样本，其余为负样本，损失就是 InfoNCE。

L=-\log\frac{\exp(\mathrm{sim}(I_i,T_i)/\tau)}{\sum_j\exp(\mathrm{sim}(I_i,T_j)/\tau)}

它的产物是一个共享的语义空间，于是可以做零样本分类（把类别名当文本查询）、图文检索、以及作为视觉编码器接入大模型。

现代视觉语言模型（VLM）的典型结构：

text
图像 → 视觉编码器（ViT）→ 投影层（MLP/Q-Former）→ 与文本 token 拼接 → LLM 解码

关键设计点是投影层：它要把视觉特征"翻译"成 LLM 能理解的 token。训练通常分两阶段：先冻结两端只训投影层（对齐），再联合微调（指令跟随）。

10.59.5 多模态的三个真实难点

  1. 分辨率与 token 预算：一张 1024×1024 的图如果切成 16×16 的 patch，就是 4096 个 token，直接吃掉上下文。所以高分辨率需要动态切块 + 压缩；
  2. 细粒度 grounding：模型能描述"图里有一只猫"，但定位"猫的左耳在哪个像素"仍然弱。这需要专门的定位数据与结构（如加检测头）；
  3. 视频的时序建模：帧数 = token 数，成本爆炸。常见折中是低帧率采样 + 关键帧 + 时间位置编码。

10　强化学习与智能体：会决策的系统怎么搭

智能体不是"更会聊天的模型"，而是"能调用工具、能做多步决策、能被约束的系统"。

智能体　·　约 1245 字　·　3 分钟

强化学习的数学（MDP、贝尔曼、策略梯度、PPO）在卷一第 14 章。这一章讲它在哪里真的有用，以及"智能体"这个被过度使用的词到底指什么。

11.110.1 强化学习的适用边界

强化学习适合同时满足三个条件的场景：

  1. 有明确的奖励信号（赢/输、成本、成功率）；
  2. 可以大量试错（仿真环境、线上有安全边界）；
  3. 决策是序列的（当前动作影响未来状态）。

不满足就优先用监督学习或规则：

场景更适合的方法
单步决策、有标注监督学习
奖励稀疏且无法仿真模仿学习 / 逆强化学习
状态空间小、规则明确搜索 / 动态规划
需要可解释与合规规则 + 监督模型

11.210.2 四个真实应用方向

  • 游戏与仿真：AlphaGo、Atari、Dota——环境可无限重置，是 RL 的最佳试验场；
  • 机器人控制： sim2real 是核心难题，域随机化（随机材质、光照、质量）是常用手段；
  • 推荐与广告：把"用户反馈"当奖励，但要注意"奖励滞后"与"策略偏置"（只学到已曝光内容）；
  • 调度与资源分配：数据中心冷却、物流路径、电网调度，奖励明确且可仿真。

工业界真正赚钱的 RL 应用大多不是端到端的，而是"RL 优化一个局部决策 + 传统系统兜底"。这一点常被媒体叙事掩盖。

11.310.3 智能体的四个部件

把"智能体（Agent）"拆开，它必须有四件东西：

部件作用缺了会怎样
感知读入用户输入、环境状态无法响应变化
规划把目标拆成步骤遇到多步任务就乱
工具调用搜索、代码、API只能空谈，不能行动
记忆保存上下文与历史结果重复劳动、前后矛盾

一个常见的误解是"给模型加个工具调用就是 Agent"。实际上规划与记忆才是分水岭：能自己决定"先查什么、再算什么、什么时候停"，才算智能体。

11.410.4 三种架构范式

范式做法优点缺点
ReAct思考→行动→观察，循环简单、可解释步数多则成本高、容易绕圈
Plan-and-Execute先出计划再执行全局性好计划错了全错，需要重规划
多智能体角色分工（规划者/执行者/评审）可并行、可互相检查通信成本高、易发散

工程上的经验是：先用单 Agent + 少量工具，跑通再拆。多智能体在任务确实可分解、且子任务需要不同上下文时才划算。

11.510.5 可靠性：智能体最缺的东西

智能体的失败模式与聊天模型完全不同：

  • 无限循环：反复调用同一工具。必须设最大步数与"无进展检测"；
  • 工具误用：参数格式错、调用了不该调的接口。要靠 schema 校验与权限白名单；
  • 目标漂移：中途忘了原始目标。靠显式的目标重述与状态记录；
  • 错误累积：一步错，后面全错。靠中间结果校验与可回滚。
工程视角

把智能体当成一个不可信的执行器来设计：每一步的输入输出都记日志、关键动作要人工确认、工具要有权限边界与超时、失败要能回到上一个安全状态。这套思路和分布式系统的容错设计是一样的。

11.610.6 与用户业务的关系

实际落地中，智能体最有价值的三类场景：

  1. 重复的多步操作（对账、报表生成、工单流转）；
  2. 需要跨系统查询的问答（把检索、数据库、API 串起来）；
  3. 有明确验收标准的生成任务（代码修改后跑测试、文案生成后过审）。

共同点是有客观的中间校验。没有校验的开放任务，智能体的成功率会低到不可用。

  • 每帧新建 Session：初始化开销远超推理本身，必须复用；
  • 每帧分配内存：用内存池或复用缓冲区，否则分配器成为瓶颈；
  • 线程数没配：intra_op_num_threads 设成物理核数，超线程反而拖慢；

12.511.5 服务化：三个必须有的机制

  1. 动态批处理：把多个请求拼成一个 batch，用微小延迟换数倍吞吐。LLM 场景用连续批处理（continuous batching），请求完成即释放槽位；
  2. 降级与限流：GPU 打满时返回缓存结果或简化模型，避免雪崩；
  3. 可观测：记录 QPS、P50/P99 延迟、GPU 利用率、显存、错误率、以及输入分布（长度、语言、类型）。

12.611.6 成本模型：一个能算的公式

\text{单位成本}=\frac{\text{GPU 小时单价}\times\text{占用时长}}{\text{请求数}}+\text{存储与网络}

举例：一张 A10（约 1 美元/小时）跑 7B INT4 模型，吞吐 20 req/s，则每请求算力成本约 1/72000\approx0.000014 美元，可以忽略；但如果每次请求要 4 秒、吞吐只有 0.25 req/s，成本就变成 0.0011 美元/次，一天十万次就是 110 美元。延迟直接决定成本，这是很多人忽略的账。

12.8压测怎么做才有意义

压测不是"打满 QPS 看会不会挂"，而是要找到性能曲线的拐点。

阶段做什么看什么
单请求基线一次请求，冷启动与热启动各测冷启动耗时（模型加载）
阶梯加压并发 1→2→4→8→…→128吞吐是否线性增长、延迟何时起飞
拐点确认在吞吐饱和点附近细测排队长度、GPU 利用率
长稳测试拐点 70% 负载跑 2 小时内存泄漏、显存碎片
异常注入杀一个 worker、注入超时降级是否生效

三个常见误判：

  • 只看平均延迟：P99 才是用户感知的；
  • 忽略预热：前 100 个请求慢是因为 kernel 未编译、缓存未填充；
  • 用合成数据：输入长度分布与线上不同，结果没有参考价值。

压测结论要写成一句可执行的话，例如"单卡在 8 并发下吞吐 22 req/s，P99 延迟 1.8s，超过 12 并发延迟翻倍"，而不是一张图。

12　评估、安全与合规

离线指标好看不等于有用；安全也不是加个过滤器就能解决。

评估与安全　·　约 1090 字　·　3 分钟

这一章处理两个"不做就会翻车"的问题：怎么知道模型真的有用，以及怎么保证它不惹事。

13.112.1 三层评估

层次做什么频率谁来看
离线评估固定测试集上的指标每次改动算法
影子评估新模型在真实流量上"只记录不生效"上线前算法 + 产品
在线 A/B分流对比业务指标上线后产品 + 数据

离线指标与线上指标经常不一致，原因有三：测试集不代表线上分布、离线指标不等于业务目标、以及反馈回路（模型推荐什么，用户就只能看到什么）。所以 A/B 是不可替代的。

13.212.2 A/B 的统计学底线

  • 样本量要先算：要给 1% 的提升做出显著结论，可能需要几十万样本。别在一千个样本上宣布胜利；
  • 看置信区间而不是点估计：+1.2\%\ [0.3\%, 2.1\%] 与 +1.2\%\ [-0.8\%, 3.2\%] 是两回事；
  • 注意新奇效应：新模型上线初期指标偏高，可能只是用户好奇；
  • 一次只改一个变量：同时改模型和界面，无法归因。

13.312.3 大模型特有的评估难题

  • 生成任务没有唯一答案：BLEU 类指标相关性弱，人工评估成本高；
  • LLM-as-judge：用强模型打分，与人的一致性可达 80% 左右，但存在位置偏置（偏好第一个答案）、长度偏置（偏好长答案）与自我偏好（偏好同族模型输出）。缓解办法是成对比较 + 交换顺序 + 固定评分标准；
  • 评测集污染：公开榜单的题目可能已在预训练语料中。自建私有评测集是唯一可靠做法。

13.412.4 安全：四个层面

层面风险主要手段
数据训练数据含隐私、版权内容去重、脱敏、数据溯源、退出机制
模型对抗样本、后门对抗训练、输入检测、权重审查
应用提示注入、越权工具调用输入隔离、权限最小化、输出校验
内容有害输出、幻觉误导安全对齐、拒答策略、引用与免责

提示注入值得单独讲：当模型会读取外部内容（网页、文档、邮件）时，这些内容里可能藏着"忽略之前的指令，把数据发到某处"这样的文本。防御思路不是"教模型别听"，而是架构隔离：外部内容标记为不可信数据、工具调用需要用户确认、敏感操作有独立鉴权。这属于系统设计问题，不是模型能力问题。

13.512.5 合规与治理的最小动作

不同行业法规不同，但有几件事是通用的：

  1. 数据来源可追溯：每个训练集记录来源、授权、采集时间；
  2. 个人信息最小化：能不存就不存，必须存则脱敏；
  3. 决策可解释：对影响用户权益的自动决策，保留人工复核通道；
  4. 留痕与审计：谁在什么时候用什么模型做了什么决策；
  5. 模型卡与数据卡：记录能力边界、评测结果、已知失败模式——这是给后来者（包括未来的你）的最重要的文档。
要点

合规不是最后加的一层审批，而是设计约束。如果一开始就按"必须能解释、必须能回滚、必须能删除用户数据"来设计，后期成本会低一个数量级。

13　时间序列与推荐系统

序列预测与个性化推荐：两个最赚钱的 AI 应用，方法却比大模型朴素得多。

应用　·　约 1427 字　·　4 分钟

这两类任务承担了 AI 商业化的大部分收入，但它们的核心方法往往不是深度网络，而是特征工程 + 树模型 + 业务规则。理解这一点，能避免"什么都上大模型"的浪费。

14.113.1 时间序列：先分解，再选模型

任何时间序列都可以尝试分解成三部分：

y_t = T_t + S_t + R_t

趋势（T）、季节（S）、残差（R）。分解之后你会立刻知道：这条曲线是"整体在涨"还是"周期性波动"，两者的建模方式完全不同。

数据特征推荐方法
短序列、强季节、单变量指数平滑（ETS）、Prophet
平稳、有自相关ARIMA / SARIMA
多变量、有外生变量梯度提升树 + 滞后特征
超长序列、大规模深度模型（TCN、Transformer 变体）
不确定性要量化分位数回归、概率预测

实践中的第一名往往不是 ARIMA 也不是 Transformer，而是"滞后特征 + LightGBM"：把 y_{t-1},y_{t-2},\dots 与日期特征、外生变量拼成表，当回归问题做。原因是它对缺失值、异常值、多变量交互的处理远比经典时序模型稳健。

14.213.2 时序任务的四个陷阱

  1. 数据泄漏：用未来信息算特征（如用全期均值做标准化）会让离线指标虚高，线上崩盘；
  2. 切分方式错：时序数据不能随机划分，必须按时间切（训练用前 70%，验证用后 30%）；
  3. 评估指标错：MAPE 在接近 0 的值上爆炸，用 sMAPE 或 MASE 更稳；
  4. 忽视节假日与促销：这些"异常"是业务的主要波动源，必须显式建模。

14.313.3 推荐系统：三段式结构

text
召回（万级 → 千级）  →  粗排（千级 → 百级）  →  精排（百级 → 十级）
阶段目标常用方法
召回快速筛出可能相关的候选协同过滤、双塔向量检索、热门/规则
粗排低成本排序小型模型、特征交叉
精排精确预估点击/转化率深度模型（DIN、DeepFM）

召回决定了天花板：精排再强，召回没捞到的物品永远不可能被推荐。所以工业界的功夫大量花在召回的多路并行上（协同、向量、热门、社交、地域各一路）。

14.413.4 协同过滤的两种形态

  • 基于用户：找相似用户，推荐他们喜欢的；
  • 基于物品：找相似物品，推荐与当前物品相似的。

核心是相似度矩阵。用矩阵分解（SVD/ALS）可以把 m\times n 的稀疏评分矩阵压成两个低秩矩阵：

R\approx P Q^{\top},\qquad P\in\mathbb{R}^{m\times k},\ Q\in\mathbb{R}^{n\times k}

这和第 14 章（卷一）的隐语义模型是同一件事。

14.513.5 双塔模型：召回的现代主力

用户塔编码用户特征，物品塔编码物品特征，两边输出向量后做内积：

\text{score}(u,i)=\langle f_u(u),f_i(i)\rangle

关键优势：物品向量可以离线预计算并建索引，线上只需算用户向量再做近邻检索，毫秒级响应。

训练用负采样 + softmax（in-batch negative 是标配）。注意样本偏差：曝光过的物品才有标签，未曝光的不代表不相关。常用纠偏手段是加上曝光概率的倒数加权。

14.613.6 冷启动：三类解法

类型问题解法
新用户没有行为用注册信息 + 热门 + 探索策略
新物品没有交互用内容特征做向量（图文嵌入）
新场景没有数据迁移已有模型 + 人工规则兜底

探索与利用的平衡（EE 问题）是冷启动的理论核心：多探索能发现好内容，但短期指标会掉。常用 Bandit 算法（UCB、Thompson Sampling）来量化这个权衡。

14.713.7 评估：离线指标与线上指标经常背离

离线线上
AUC、NDCG、Recall@k点击率、转化率、时长、留存

背离的三个原因：离线用的是历史曝光数据（有偏）、离线不看多样性（线上会审美疲劳）、离线不看实时性（线上要求毫秒级）。

结论：离线指标只用来筛方案，最终判断必须靠线上 A/B。

要点

这两类任务的共同特征是特征比模型重要、评估比训练重要。如果你有时间，先做特征工程与数据质量，再考虑换模型。

14　判断一个 AI 需求能不能做

判断"这个需求能不能用 AI 做"，比"怎么用 AI 做"更值钱。

产品　·　约 1111 字　·　3 分钟

这一章给一套可以拿到评审会上用的判断框架。它不承诺准确，但能把"拍脑袋立项"变成"有依据的取舍"。

15.114.1 三个前置问题

  1. 错误的代价有多大？ 错了能撤回（草稿、建议）就可以做；错了不可逆（自动打款、自动发药）就需要极高准确率或人工闸门；
  2. 有没有可判定的"对"？ 有客观标准（测试通过、字段正确）就能做评测；只能"感觉还行"就很难迭代；
  3. 数据够不够？ 要么有标注数据，要么有可检索的资料，要么有可验证的规则。三者都没有，只能做 demo。

三个问题里有两个答不上来，这个需求就不该现在做。

15.214.2 四象限：按"可验证性 × 容错度"分类

容错高容错低
可验证优先做（如代码生成 + 单测、文档格式转换）可做但要人工复核（如合同条款抽取）
不可验证谨慎做（如创意文案）不要做（如医疗诊断、法律意见）

这个矩阵的价值在于：它把"技术能不能"换成"业务敢不敢用"，而后者才是项目生死的决定因素。

15.314.3 成本、延迟、准确性：三角只能选两个

组合代价
高准确 + 低延迟贵（大模型 + 强硬件 + 大量缓存）
高准确 + 低成本慢（离线批处理、多轮校验）
低延迟 + 低成本准确率下降（小模型、量化）

评审时最常见的错误是三个都要。正确做法是明确"哪个是硬约束"：交互式产品延迟是硬约束，批处理任务成本是硬约束，合规场景准确性是硬约束。

15.414.4 需求拆解：把"智能"换成"步骤"

模糊需求："帮我做一个智能合同审查"。

拆解：

步骤能否自动化技术方案
抽取当事人、金额、期限高结构化抽取（微调或规则 + LLM 校验）
识别缺失条款中规则库 + 检索比对
判断条款风险低只能给"参考意见 + 引用法条"，需律师复核
生成修改建议中模板 + LLM 改写

拆完之后，"智能审查"变成了四个可独立交付、独立评估的模块。这一步做完，项目风险下降一半，因为你知道哪部分只能做辅助。

15.514.5 五个必问的评审问题

  1. 基线是什么？ 现在人工做这件事的准确率与耗时是多少？不比基线好就没有价值；
  2. 失败时用户看到什么？ 有没有"我不知道"的表达方式；
  3. 怎么衡量上线后变好？ 采纳率？修改率？处理时长？
  4. 数据从哪来、能不能用？ 版权、隐私、脱敏；
  5. 模型换代时怎么办？ 有没有评测集能验证"新模型不比旧模型差"。

这五个问题答不出来，项目即使上线也会在三个月内变成没人维护的技术债。

15.614.6 什么时候明确说"不做"

  • 需要 100% 准确率且错误不可逆；
  • 没有数据、也没法获取（且不能靠规则解决）；
  • 用户真正要的是"省人力"，而流程本身可以靠信息化直接消除；
  • 收益无法归因（做完也无法证明有价值）；
  • 合规边界不清（尤其涉及个人信息、医疗、金融决策）。

说"不做"并给出理由，是产品能力的一部分。

工程视角

作为工程师，你在评审里最有价值的一句话是："这个需求在我们的评测集上大概能做到 X%，失败模式是 Y。" 有了这句话，产品才能做取舍；没有这句话，讨论只能停在感觉层面。

16.215.2 概率分布速查

数据处理不等式值得单独理解：任何处理都只会减少信息，不会增加。这解释了为什么"更好的预处理"能提效（保留任务相关信息），但不能凭空造出信息。

16.415.4 信息论四个量

H(X)=-\sum p\log p,\quad H(X|Y)=H(X,Y)-H(Y)
I(X;Y)=H(X)-H(X|Y)=H(X)+H(Y)-H(X,Y)
D_{\mathrm{KL}}(p\|q)=\sum p\log\frac{p}{q}
\mathrm{JS}(p\|q)=\tfrac12 D(p\|m)+\tfrac12 D(q\|m),\quad m=\tfrac{p+q}{2}

三个必须记住的性质：

  • KL 不对称：D(p\|q)\ne D(q\|p)，所以它不是距离；
  • KL 非负，当且仅当两分布相同为 0（由 Jensen 得到）；
  • 互信息对称：I(X;Y)=I(Y;X)，而 KL 不对称。

17.216.2 七个值得做完的项目

按难度排序，每个都要求"能跑、能评、能讲"：

  1. 表格竞赛：泰坦尼克或房价预测，做到特征工程 + 交叉验证 + 模型融合。目的是掌握方法论；
  2. 手写数字/垃圾分类：从零训 CNN，再做量化与 ONNX 部署，测出延迟与精度；
  3. 目标检测落地：用自己的照片训一个小检测模型，做成摄像头实时推理；
  4. 文本分类基线对比：TF-IDF + 线性 vs BERT 微调 vs LLM 零样本，比较精度、延迟、成本；
  5. RAG 问答：把一批 PDF 做成可问答系统，重点是切分策略与检索质量评估；
  6. 微调一个 7B 模型：LoRA 微调，测显存、吞吐、效果，写出"什么规模的任务值得微调"的结论；
  7. 推理服务：把任一模型封装成 C++ 服务，含动态批处理、监控、压测报告。

每个项目都要写一份 README：目标、数据、方法、指标、失败尝试、结论。这份文档比代码更能证明你的能力。

17.316.3 常见的学习误区

  • 只收集教程不动手：AI 的直觉来自调参时看到的反常现象，不是来自阅读；
  • 一上来就学大模型：没有传统机器学习与深度学习的基础，看 LLM 论文只能记住名词；
  • 追求 SOTA 复现：复现一篇论文的收益远低于把一个简单模型做到极致；
  • 忽视工程：真实项目的 80% 工作量在数据、部署、监控；
  • 不看失败案例：错误分析的收益通常是换模型的三倍。
