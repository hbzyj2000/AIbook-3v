# 4　微调：LoRA、数据构造与遗忘

先明确一个判断：**大多数"模型不懂我们业务"的问题，靠微调解决不了，靠检索能解决。** 微调擅长的是**改变行为方式**（格式、语气、判断标准），不擅长**注入事实知识**。

## 4.1 SFT 的目标与数据

监督微调就是标准的下一 token 预测，只是只对"回答部分"计损失：

```python
# 只对 answer 计算 loss，问题部分 mask 掉
labels = input_ids.clone()
labels[:, :prompt_len] = -100        # -100 会被 CrossEntropy 忽略
loss = model(input_ids, labels=labels).loss
```

数据构造的四条经验：

1. **多样性比数量重要**。500 条覆盖 50 种任务类型，胜于 5000 条同一模板；
2. **长度分布要覆盖**。全训短回答，上线后长回答会崩；
3. **包含"拒答"样本**。只训"知无不言"，模型学不会说"我不知道"；
4. **格式严格一致**。训练时的分隔符、角色标记必须与推理时完全相同。

## 4.2 LoRA：为什么小增量够用

LoRA 冻结原权重 $W$，只学一个低秩增量：

$$ W' = W + \frac{\alpha}{r}BA,\qquad B\in\mathbb{R}^{d\times r},\ A\in\mathbb{R}^{r\times k},\ r\ll \min(d,k) $$

参数量从 $d k$ 降到 $r(d+k)$。$r=8$、$d=k=4096$ 时，从 16.8M 降到 65K，**约 1/256**。

两个超参：

- **$r$（秩）**：控制容量。任务越"新"，秩要越大。经验：格式调整 4–8，风格迁移 8–16，新任务学习 16–64；
- **$\alpha$（缩放）**：实际增量是 $\frac{\alpha}{r}BA$。常见做法是 $\alpha=2r$，这样改 $r$ 时有效学习率不变。

**target modules 的选择**比 $r$ 更影响效果：至少覆盖 `q_proj`、`v_proj`，效果不够再加 `k_proj`、`o_proj`、以及 FFN 的三个投影。全加会显著增加可训练参数，但通常也显著提升效果。

## 4.3 QLoRA：把基座压到 4bit 再训

QLoRA 三步：

1. **NF4 量化**：把权重压到 4bit，用分位数量化表（对正态分布最优）；
2. **双重量化**：对量化常数再量化一次，进一步省显存；
3. **分页优化器**：优化器状态在显存不足时换出到 CPU。

效果：7B 模型微调的显存需求从约 60GB 降到约 12GB，单张消费级卡可跑。代价是训练速度慢 20%–40%。

**关键细节：LoRA 的增量始终在 FP16/BF16 上计算**，所以量化只影响基座的前向，不损梯度的精度。这是它能保持效果的原因。

## 4.4 训练超参起点

| 超参 | 建议起点 | 说明 |
| --- | --- | --- |
| 学习率 | 1e-4 ~ 2e-4（LoRA） | 全量微调用 1e-5 ~ 5e-5 |
| batch | 尽量大（用梯度累积） | 有效 batch 16–128 |
| epoch | 1–3 | 超过 3 轮通常开始过拟合 |
| warmup | 3%–5% | 小数据也要有 |
| 权重衰减 | 0.01 | 对 LoRA 参数也生效 |
| 序列长度 | 覆盖你的 P95 | 截断会破坏长样本 |

**early stopping 靠验证集 loss 还是任务指标？** 优先用任务指标（格式正确率、抽取 F1）。验证 loss 下降但格式崩坏是常见现象。

## 4.5 灾难性遗忘：为什么会忘，怎么防

微调会让模型在旧任务上退化，原因是参数更新把原来的解推离了。四种缓解：

| 手段 | 做法 | 代价 |
| --- | --- | --- |
| 混入通用数据 | 训练集里掺 10%–30% 通用指令 | 需要额外数据 |
| 低秩更新 | 用 LoRA 而非全量 | 容量受限 |
| 更小学习率 | 1e-5 级别 | 收敛慢 |
| 正则约束 | 对偏离原权重的量加惩罚 | 需要调系数 |

评估遗忘的标准做法：**微调前后都在一组通用任务（如常识问答、指令遵循）上测一遍**，掉超过 3–5 个点就要警惕。

:::eng 工程视角
微调之前先问三个问题：

1. 这个问题能不能用提示 + 检索解决？能，就别微调；
2. 我有没有至少 500 条**高质量、格式一致**的样本？没有，先做数据；
3. 微调后怎么衡量"没变坏"？没有这个指标，就不要上线。

三个都过了，再动 LoRA。这套流程能省掉大量无效训练。
:::

## 4.6 蒸馏：另一种"变小"的路径

如果目标是"用更小的模型做同样的事"，蒸馏往往比微调更有效：用大模型生成回答，让小模型学。关键是**学软标签**（完整分布）而不只是硬答案：

$$ L=(1-\lambda)\,L_{\text{CE}}(y,\hat y)+\lambda\,T^2\,D_{\mathrm{KL}}\big(p_{\text{teacher}}^{(T)}\,\|\,p_{\text{student}}^{(T)}\big) $$

温度 $T$ 用来"软化"分布，让学生看到类间关系。这套方法在小模型追赶大模型上非常有效，代价是要有足够的大模型生成数据。
