# 15　路线与判断力

## 15.1 十二周计划（每周 8–10 小时）

| 周 | 主题 | 交付 |
| --- | --- | --- |
| 1 | Transformer 形状与参数量手算 | 手写一个 Block，参数量与配置对得上 |
| 2 | 分词与数据 | 统计自己语料的 token 分布 |
| 3 | 预训练账本 | 算出 7B/2T 的训练成本与显存需求 |
| 4 | LoRA 微调 | 用 QLoRA 微调一个 7B，记录显存与效果 |
| 5 | 对齐 | 跑一次 DPO，比较与 SFT 的差异 |
| 6 | 推理优化 | 测 TTFT/TPOT，做量化对比 |
| 7 | 长上下文 | 测不同长度下的召回准确率 |
| 8–9 | RAG | 完成第 14 章的系统 + 评测集 |
| 10 | Agent | 加三个工具，做最大步数与非进展检测 |
| 11 | C++ 落地 | 用 llama.cpp 或 ONNX 做一个服务 |
| 12 | 复盘 | 写一份"我这十二周学到的十件事" |

**第 12 周的复盘比前面十一周都重要**：把踩过的坑写下来，那些才是你的知识。

## 15.3 六条判断力

这些是比任何具体技术都长寿的东西：

1. **先算账再优化**。显存、算力、带宽三个数算不清，所有优化都是猜；
2. **瓶颈通常在数据与链路，不在模型**。RAG 的问题 90% 在检索；
3. **能量化的改动才叫优化**。没有评测集的改动只是"感觉变好了"；
4. **优先用简单方法**。能用 BM25 + 规则解决的，不要上向量库 + 重排；
5. **对齐与安全是设计约束**，不是上线前的补丁；
6. **警惕"能力叙事"**。任何"模型能自动完成 X"的说法，都要求一个失败率的数字。

## 15.4 这一卷和另外两卷的关系

| 卷 | 回答什么问题 |
| --- | --- |
| 卷一（数学） | 为什么是这样：推导与原理 |
| 卷二（全景） | 有哪些东西、各自适合什么 |
| 卷三（本卷） | 怎么把它做出来、做快、做省 |

三卷不是替代关系。遇到"这个公式为什么成立"，回卷一；遇到"该选哪个方案"，回卷二；遇到"怎么上线"，就在这一卷。

## 15.5 最后一句话

AI 工程里最稀缺的能力，不是会用最新的模型，而是**能把一个模糊需求拆成可测量的链路，并在每一环上做出有依据的取舍**。这个能力和写 C++ 时做架构决策是同一种能力。

模型会换、框架会换、榜单会换。算账的能力、定位瓶颈的能力、以及"不轻信效果宣称"的习惯，不会过时。
