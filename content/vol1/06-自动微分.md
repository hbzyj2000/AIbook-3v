# 5　自动微分与反向传播：框架到底替你做了什么

很多人对反向传播的理解停在"误差往回传，乘以权重再乘激活导数"。这个说法不算错，但你无法用它解释三件事：为什么 `loss.backward()` 之后要 `zero_grad()`、为什么显存和激活值有关、为什么梯度检查要用双精度。这一章把它讲成一套可执行的机制。

## 5.1　计算图：把函数拆成算子

任何前向计算都能写成一串基本算子：乘、加、矩阵乘、exp、log、求和、reshape、切片。写成有向无环图后，每个节点存三样东西：

- 算子类型（决定反向用什么公式）；
- 输入张量（前向时用到）；
- 输出张量。

框架在 `requires_grad=True` 的张量参与运算时，会顺手记下这个节点，把输出与输入连起来。**这就是"自动"的全部秘密：它不推导公式，它只是把算子拼起来，反向时按每个算子的固定规则回传。**

## 5.2　两种模式：前向与反向

设 $f:\mathbb{R}^n\to\mathbb{R}^m$，雅可比 $J\in\mathbb{R}^{m\times n}$。

- **前向模式（JVP）**：一次算出 $J v$（一个方向的方向导数），代价约等于一次前向。要拿到完整 $J$，需要 $n$ 次；
- **反向模式（VJP）**：一次算出 $u^\top J$，代价约等于一次前向。要拿完整 $J$，需要 $m$ 次。

深度学习里 $m=1$（损失是标量），$n$ 是上亿参数。所以选反向模式：**一次就够**。这不是优化，是数学结构决定的必然选择。反过来，如果输出维度远大于输入（比如生成一批样本算雅可比），前向模式更好——这就是为什么 JAX 里两种都提供。

## 5.3　逐层推导：把形状写清楚

### 线性层

设 $Y=XW^\top+b$，$X\in\mathbb{R}^{B\times d_{in}}$，$W\in\mathbb{R}^{d_{out}\times d_{in}}$，$Y\in\mathbb{R}^{B\times d_{out}}$。设上游传来 $\mathrm{d}Y$（与 $Y$ 同形状）：

$$ \mathrm{d}X=\mathrm{d}Y\,W,\qquad \mathrm{d}W=\mathrm{d}Y^\top X,\qquad \mathrm{d}b=\sum_{n=1}^{B}\mathrm{d}Y_{n,:} $$

三个式子都能用形状验证：$\mathrm{d}Y(B,d_{out})$ 乘 $W(d_{out},d_{in})$ 得 $B\times d_{in}$，与 $X$ 对上；$\mathrm{d}Y^\top(d_{out},B)$ 乘 $X(B,d_{in})$ 得 $d_{out}\times d_{in}$，与 $W$ 对上。**形状对得上，基本就错不了**，这是工程上最实用的自检手段。

### 逐元素激活

若 $Y=f(X)$ 是逐元素作用，则

$$ \mathrm{d}X=\mathrm{d}Y\odot f'(X) $$

ReLU 的导数是 $1_{x>0}$，Sigmoid 是 $\sigma(x)(1-\sigma(x))$，Tanh 是 $1-\tanh^2$。注意 ReLU 在 $x=0$ 处不可导，工程上取 0 或 1 都行，测度为零不影响训练。

### Softmax + 交叉熵

这是深度学习中最重要的一个复合算子，值得单独推。设 logits $z\in\mathbb{R}^{K}$，$p=\mathrm{softmax}(z)$，标签 one-hot $y$，损失 $L=-\sum_k y_k\log p_k$。先算 $\mathrm{d}L/\mathrm{d}p_k=-y_k/p_k$，再乘 softmax 的雅可比

$$ \frac{\partial p_i}{\partial z_j}=p_i(\delta_{ij}-p_j) $$

两者相乘，$p_i$ 与 $1/p_i$ 相消：

$$ \frac{\partial L}{\partial z_j}=\sum_i\Big(-\frac{y_i}{p_i}\Big)p_i(\delta_{ij}-p_j)=-y_j+p_j\sum_i y_i=p_j-y_j $$

结果干净到不真实：**梯度就是预测减标签**。这也解释了为什么它不怕 $p$ 很小——分母被约掉了。若你分开写 softmax 和 log，这个相消不会发生，数值上就会溢出。

:::warn 常见坑
- `zero_grad()` 忘了调用，梯度会**累加**而不是覆盖。这不是 bug 而是设计：梯度累积（用小 batch 模拟大 batch）正是靠它。
- 在 `torch.no_grad()` 里做验证，否则会白白建图占显存。
- 原地操作（`x += 1`）可能破坏反向需要的中间值，报 "a leaf Variable that requires grad is being used in an in-place operation"。改成 `x = x + 1`。
:::

## 5.4　手写一遍：两层 MLP 的完整反向

下面这段用 numpy 实现，不用框架，你能看清每个梯度是怎么来的。形状全部标在注释里。

```python
import numpy as np

B, D, H, K = 8, 4, 6, 3

def relu(x): return np.maximum(0, x)

# ---- 前向 ----
X  = np.random.randn(B, D)          # (8,4)
W1 = np.random.randn(H, D) * 0.1    # (6,4)
b1 = np.zeros(H)                    # (6,)
Z1 = X @ W1.T + b1                  # (8,6)
A1 = relu(Z1)                       # (8,6)
W2 = np.random.randn(K, H) * 0.1    # (3,6)
b2 = np.zeros(K)
Z2 = A1 @ W2.T + b2                 # (8,3)
P  = np.exp(Z2) / np.exp(Z2).sum(axis=1, keepdims=True)   # (8,3)
Y  = np.array([0,1,2,1,0,2,1,0])
loss = -np.log(P[np.arange(B), Y]).mean()

# ---- 反向 ----
dZ2 = P.copy()                      # (8,3)
dZ2[np.arange(B), Y] -= 1
dZ2 /= B                            # 交叉熵求均值，缩放 1/B
dW2 = dZ2.T @ A1                    # (3,8)@(8,6) -> (3,6)
db2 = dZ2.sum(axis=0)               # (3,)
dA1 = dZ2 @ W2                      # (8,3)@(3,6) -> (8,6)
dZ1 = dA1 * (Z1 > 0)                # (8,6)
dW1 = dZ1.T @ X                     # (6,8)@(8,4) -> (6,4)
db1 = dZ1.sum(axis=0)               # (6,)
```

把这段和框架的 `.backward()` 对照，你会发现差别只在"图是手写的还是自动建的"。

## 5.5　梯度检查：数值微分的正确用法

解析梯度写错时，最可靠的验证是中心差分：

$$ \frac{\partial f}{\partial x_i}\approx\frac{f(x+\epsilon e_i)-f(x-\epsilon e_i)}{2\epsilon} $$

误差是 $O(\epsilon^2)$，但要**用双精度**，$\epsilon$ 取 $10^{-5}$ 左右。$\epsilon$ 太小会被舍入误差吞掉，太大则截断误差显著。经验做法：

- 用相对误差 $\frac{|g_{\text{num}}-g_{\text{ana}}|}{\max(1,|g_{\text{num}}|,|g_{\text{ana}}|)}$，小于 $10^{-6}$ 算通过；
- 只抽几个参数检查，不必全量；
- 关掉 dropout、batchnorm 的随机性，否则数值梯度不可信。

## 5.6　内存：反向传播最贵的不是算力

前向时每个算子要保存反向所需的中间量（激活值、掩码），显存占用大致与**层数 × batch × 序列长度 × 隐藏维**成正比。这带来一个工程上的经典事实：

> 训练大模型时，显存瓶颈常常不是参数，而是激活值。

三种缓解手段：

1. **梯度检查点（activation checkpointing）**：不存中间激活，反向时重算。用约 30% 的额外算力换数倍的显存；
2. **混合精度**：前向用 FP16/BF16 存激活，主权重与优化器状态用 FP32；
3. **序列并行 / 重计算**：把长序列切块分布到多卡。

这些在卷三会展开成"显存账本"，这里只需要建立因果：**反向传播需要前向的中间结果，所以中间结果必须存下来，存不下就得重算。**
