# 5　深度学习：一条能重复的训练流水线

原理部分（初始化、归一化、残差）在卷一第 10 章讲过。这一章讲**操作层**：怎么组织代码、按什么顺序调参、出了问题怎么定位。

## 5.1 训练循环的心智模型

任何训练脚本都是这五步的循环：

```python
for step, batch in enumerate(loader):
    x, y = batch                       # 1. 取数据（含增强、设备拷贝）
    logits = model(x)                  # 2. 前向
    loss = criterion(logits, y)        # 3. 损失
    loss.backward()                    # 4. 反向（建图 -> 回传）
    optimizer.step()                   # 5. 更新
    optimizer.zero_grad(set_to_none=True)  # 清梯度，放最后更省内存
```

**把这五步写成可开关的开关**，是让调试变快的关键：能在 100 个样本上跑完整个循环、能关掉增强、能只跑前向。很多"训不动"的问题，靠缩小规模能在十分钟内定位。

## 5.2 超参的调整顺序

按影响大小排（而不是按论文里写得多的排）：

1. **学习率**：影响最大。先用 lr range test 扫一遍，选损失下降最快的区间的下限；
2. **batch 大小与调度**：batch 大则 lr 要相应放大（线性缩放规则），并配 warmup；
3. **模型规模**：宽/深按数据量选，宁可先小后大；
4. **正则强度**：weight decay、dropout、label smoothing，先只调 weight decay；
5. **其余**：优化器细节（$\beta_1,\beta_2,\epsilon$）、增强强度。

一个常被忽略的事实：**小模型 + 好数据 > 大模型 + 一般数据**。在数据有限时，先把数据质量提上去，收益通常超过换模型。

## 5.3 迁移学习：三种微调策略

| 策略 | 做法 | 适用 |
| --- | --- | --- |
| 冻结主干 | 只训最后的分类头 | 数据极少（数百）、任务与预训练接近 |
| 分层学习率 | 主干 lr 小、头部 lr 大 | 中等数据、任务有差异 |
| 全量微调 | 所有参数更新 | 数据充足、任务差异大 |

视觉任务的经验起点：冻结主干训 5 轮头部，再解冻全部用 $1/10$ 的学习率微调。文本任务用 BERT 类模型时，学习率 2e-5 到 5e-5 是常见区间，太大容易破坏预训练知识。

## 5.4 显存：先算清楚再看 OOM 报错

训练显存大致由四部分组成：

$$ \text{总显存}\approx \underbrace{\text{参数}}_{\text{权重}}+\underbrace{\text{梯度}}_{\text{同权重}}+\underbrace{\text{优化器状态}}_{\text{Adam 约 2 倍权重}}+\underbrace{\text{激活值}}_{\text{与 batch、序列长成正比}} $$

以 FP16 + Adam 训练 7B 模型为例：权重 14GB、梯度 14GB、Adam 的 $m$ 与 $v$ 各 28GB（FP32）、激活另算——**光静态部分就超过 80GB**。这解释了为什么需要 ZeRO/FSDP 做参数分片（卷三展开）。

常见省显存手段的优先级：小 batch + 梯度累积 → 混合精度 → 梯度检查点 → 参数分片。

## 5.5 九种失败模式对症表

| 现象 | 最可能的原因 | 先试什么 |
| --- | --- | --- |
| 损失不降 | lr 太小 / 数据或标签错 | 放大 lr 10 倍；过拟合 10 个样本 |
| 损失变 NaN | lr 太大 / 混合精度溢出 | 降 lr；检查 loss scale |
| 训练降验证升 | 过拟合 | 加正则、加数据、减容量 |
| 训练验证都不动 | 欠拟合或梯度消失 | 加容量、换激活、查梯度范数 |
| 指标卡在某个值 | 类别不平衡 / 指标错 | 看混淆矩阵，换指标 |
| 结果每次都不一样且差很多 | 初始化或数据顺序问题 | 固定种子，检查 shuffle |
| 验证远好于训练 | 数据泄漏 | 查单特征 AUC、查重复样本 |
| 推理与训练结果不一致 | BN 的 train/eval 模式 | 确认 `model.eval()` |
| 显存缓慢增长 | 计算图未释放 / 缓存累积 | 检查 `detach()`、清缓存 |
