# 7　自然语言处理：从词表到检索

文本任务的难点不在模型结构，而在**离散符号如何变成连续向量**、以及**评价指标如何逼近人的判断**。这两件事至今没有完美解法。

## 7.1 分词：第一个不可回避的选择

模型不认识字符串，只认识 ID。分词（tokenization）把文本切成子词单元。三种主流算法：

| 算法 | 做法 | 特点 |
| --- | --- | --- |
| BPE | 从字符开始，反复合并最高频相邻对 | GPT 系使用，压缩率好 |
| WordPiece | 合并能最大化似然增益的对 | BERT 系使用 |
| Unigram | 从大词表开始，按损失删减 | SentencePiece 常用，多语言友好 |

中文的特殊性：没有空格，所以早期用字级或词级（依赖分词工具），现在主流是**直接在字/子词级别做 BPE**，让模型自己学组合。

一个常被忽略的事实：**词表大小是一个工程权衡**。词表大 → 序列短（推理快）、但嵌入矩阵大、低频词学不好；词表小 → 序列长（推理慢）、但泛化好。LLaMA 系用 32K，一些多语言模型用 100K 以上。

## 7.2 词向量：从静态到上下文相关

- **静态词向量**（word2vec、GloVe）：一个词一个向量。问题是多义词无法区分（"苹果"既是水果也是公司）；
- **上下文词向量**（ELMo、BERT）：同一个词在不同句子里得到不同向量。这是预训练模型的根本贡献。

word2vec 的训练目标（skip-gram + 负采样）在卷一第 14 章推导过，其思想——"把正样本与随机负样本分开"——是对比学习的原型。

## 7.3 四类任务与各自的评价

| 任务 | 输入→输出 | 指标 | 指标的坑 |
| --- | --- | --- | --- |
| 文本分类 | 文本→标签 | 准确率、宏 F1 | 类别不均衡时必须看每类 |
| 序列标注（NER） | 文本→每 token 标签 | 实体级 F1 | 必须按实体算，不能按 token 算 |
| 抽取式问答 | 问题+段落→片段 | EM / F1 | EM 要求完全匹配，过于严格 |
| 生成（翻译/摘要） | 文本→文本 | BLEU / ROUGE / BERTScore | 与人的判断相关性弱 |

**BLEU/ROUGE 的局限值得单独强调**：它们基于 n-gram 重叠，对同义改写、语序变化极不敏感。一个语义完全正确但用词不同的译文可能得分很低。所以现在的生成任务更常用：

- **BERTScore**：用上下文嵌入算相似度，对改写更宽容；
- **COMET / BLEURT**：训练过的评估模型；
- **LLM-as-judge**：用强模型按标准打分，成本高但更接近人。

## 7.4 检索：最被低估的一环

很多"大模型答不准"的问题，根源在检索而不是生成。检索的基本流程：

1. **切分（chunking）**：把文档切成 200–500 字的块，重叠 10–20% 避免切断语义；
2. **编码**：用双塔模型（如 bge、e5 系列）把块编码成向量，离线建索引；
3. **召回**：向量近邻（HNSW/IVF）+ 关键词（BM25）双路召回；
4. **重排（rerank）**：用交叉编码器对 Top-50 精排，取 Top-5。

双塔与交叉编码器的区别很重要：

- **双塔**：query 与 doc 分别编码，可离线建索引，快，但交互信息少；
- **交叉编码器**：把 query 与 doc 拼起来一起编码，精度高，但每个候选都要过一次模型，只能用于重排。

**先用双塔召回 50 个，再用交叉编码器重排**，这是成本与效果的平衡点。卷三会展开完整链路。

:::warn 常见坑
- 只用向量检索：专有名词、编号、代码这类"精确匹配"需求会漏，必须加 BM25；
- chunk 太大：召回的是长段落，生成时上下文被稀释；太小则语义不完整；
- 用通用嵌入模型做垂直领域检索：金融、医疗、法律的术语分布差异大，需要在领域数据上微调嵌入模型。
:::

## 7.5 传统方法与预训练模型的分界

| 场景 | 建议 |
| --- | --- |
| 有标注数据几千条以上 | 微调预训练模型（BERT 类），通常最优 |
| 标注极少（几十条） | 零样本/少样本提示，或先用 LLM 生成弱标签 |
| 极低延迟（微秒级） | TF-IDF + 线性模型，仍然能打 |
| 需要解释 | 关键词 + 规则 + 线性模型 |
| 多语言 | 多语言预训练模型（XLM-R、mT5） |

**"LLM 全能"是个误解**：在固定类别的分类任务上，一个小 BERT 微调后往往比调用大模型更准、更快、更便宜。大模型的优势在开放域、少样本、需要推理与生成的场景。
