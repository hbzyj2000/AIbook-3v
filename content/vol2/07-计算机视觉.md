# 6　计算机视觉：四个任务，四种评价

你有数字图像处理的底子，这一章的重点不是"卷积是什么"，而是**任务怎么定义、指标怎么算、方案怎么选**。

## 6.1 分类：从单标签到多标签

分类的输出是一个概率向量。三个现代要点：

- **数据增强是主要收益来源**：RandAugment、MixUp、CutMix 这类方法在中小数据集上能提升几个点，比换模型划算；
- **标签平滑**抑制过度自信，改善校准；
- **长尾问题**：真实数据类别极不均衡，用重采样、logit adjustment 或两阶段训练（先均衡预训练，再长尾微调）。

指标：Top-1 / Top-5 准确率。**注意类别不均衡时用宏平均（macro-F1），不要用微平均**，后者会被大类主导。

## 6.2 检测：框的匹配与 NMS

检测输出"每个目标的框 + 类别"。核心机制有三个：

1. **锚框 / 无锚**：Faster R-CNN 用锚框，YOLO 后期版本用中心点 + 尺寸回归，省掉锚框调参；
2. **IoU 与匹配**：预测框与真值框的交并比决定"算不算命中"。IoU 阈值 0.5 常用于"是否检出"，0.75 用于"框得准不准"；
3. **NMS**：同一目标会有多个重叠框，按分数排序后抑制 IoU 超过阈值的。

指标是 **mAP**（各类 AP 的均值），分 mAP@0.5 和 mAP@0.5:0.95（后者对框的精度要求更高）。**报告 mAP 时必须写清阈值**，否则数字不可比。

:::warn 常见坑
- 小目标检测：下采样太多导致小目标在特征图上只剩几个像素。解法是高分辨率特征图、FPN 多尺度融合、切片推理（把大图切块分别检测再合并）；
- NMS 阈值调不好会"吞掉"密集目标（人群、货架），改用 Soft-NMS 或可学习的 NMS。
:::

## 6.3 分割：像素级的三类任务

| 类型 | 输出 | 代表方法 | 指标 |
| --- | --- | --- | --- |
| 语义分割 | 每像素类别 | U-Net、DeepLab | mIoU |
| 实例分割 | 每实例的掩码 | Mask R-CNN | mask mAP |
| 全景分割 | 两者合并 | Panoptic FPN | PQ |

mIoU 的定义是"交并比在所有类别上取平均"，它惩罚"漏标"和"多标"同样重。医学图像里更常用 Dice 系数，因为它对类别极不平衡更友好。

现代趋势是**提示式分割**（SAM 一类）：给定点、框或文本提示，输出掩码。它把分割从"每类训一个模型"变成"一个模型适配多任务"，这大幅降低了标注需求。

## 6.4 从图像处理到深度视觉：哪些东西没变

你在图像处理课上学的东西依然有效，只是角色变了：

| 传统技术 | 在深度视觉里的位置 |
| --- | --- |
| 高斯滤波 / 双边滤波 | 预处理去噪；也可作为固定卷积核嵌入网络 |
| 边缘检测（Sobel/Canny） | 浅层卷积学到的正是这类核；Canny 仍用于后处理与标注辅助 |
| 形态学操作 | 掩码后处理（去除小连通域、填补空洞） |
| 直方图均衡 / Gamma | 数据增强与预处理；但要注意它会改变分布 |
| 多尺度金字塔 | FPN、图像金字塔推理，思想完全相同 |
| 光流 | 视频理解的基础；传统 Lucas-Kanade 仍用于快速场景 |

**一句话：传统方法是可解释的先验，深度方法是可学习的先验。** 二者常常组合使用，而不是替代关系。

## 6.5 部署侧的现实约束

视觉模型上线的瓶颈很少是精度，而是：

- **延迟**：1080p 视频 30fps 意味着每帧 33ms 的预算，包含解码、预处理、推理、后处理；
- **量化**：INT8 量化通常带来 2–4 倍加速，精度掉 0.5–2 个点，需要逐层校准；
- **输入分辨率**：分辨率翻倍，卷积计算量翻 4 倍。很多"精度提升"其实来自更高分辨率，而不是更好的结构；
- **算子支持**：某些自定义算子（如可变形卷积）在目标推理引擎上不支持，会被回退到 CPU，性能骤降。

:::eng 工程视角
选型时先定延迟预算，再选模型。一个能在 20ms 内跑完的 85% mAP 模型，胜过一个需要 80ms 的 88% mAP 模型——因为前者能上更多路摄像头，总覆盖收益更高。**这是工程判断，不是精度竞赛。**
:::

## 上线前的精度检查清单

离线 mAP 高不等于线上可用。上线前必查五项：

| 检查 | 做法 | 常见问题 |
| --- | --- | --- |
| 分布一致性 | 对比线上与训练集的亮度、分辨率、长宽比分布 | 线上手机拍摄的畸变与训练集不符 |
| 小目标 | 单独统计小尺寸目标的召回 | 整体 mAP 掩盖了小目标崩塌 |
| 类别不均衡 | 看每类的 P/R，不只看均值 | 稀有类几乎检不出 |
| 后处理参数 | NMS 阈值、置信度阈值在线上数据上重调 | 沿用训练集的最优值 |
| 延迟 | 端到端测（含解码、后处理） | 只测了模型前向 |

**最容易被忽略的是第四项**：置信度阈值直接决定"误检 vs 漏检"的平衡，而它应该由业务代价决定，不是由验证集 F1 决定。
