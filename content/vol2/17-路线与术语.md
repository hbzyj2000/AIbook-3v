# 16　路线图、项目清单与术语表

## 16.1 六个月路线（按周排）

| 阶段 | 时间 | 目标 | 交付物 |
| --- | --- | --- | --- |
| 基础 | 第 1–4 周 | 跑通训练流程，理解损失与优化 | 手写两层 MLP 并训练到收敛 |
| 经典 | 第 5–6 周 | 会用树集成与特征工程 | 一个 Kaggle 级别的表格竞赛方案 |
| 视觉 | 第 7–10 周 | 掌握迁移学习与数据增强 | 微调一个检测/分类模型并部署 |
| 语言 | 第 11–14 周 | 理解 Transformer 与大模型使用 | 一个 RAG 问答系统 |
| 工程 | 第 15–20 周 | 能上线、能监控、能优化 | 一个带监控的推理服务 |
| 深耕 | 第 21–24 周 | 选一个方向做深 | 一篇技术报告或一个开源贡献 |

这个节奏的前提是**每周至少 10 小时动手**。只看不练的进度会打三折。

## 16.2 七个值得做完的项目

按难度排序，每个都要求"能跑、能评、能讲"：

1. **表格竞赛**：泰坦尼克或房价预测，做到特征工程 + 交叉验证 + 模型融合。目的是掌握方法论；
2. **手写数字/垃圾分类**：从零训 CNN，再做量化与 ONNX 部署，测出延迟与精度；
3. **目标检测落地**：用自己的照片训一个小检测模型，做成摄像头实时推理；
4. **文本分类基线对比**：TF-IDF + 线性 vs BERT 微调 vs LLM 零样本，比较精度、延迟、成本；
5. **RAG 问答**：把一批 PDF 做成可问答系统，重点是切分策略与检索质量评估；
6. **微调一个 7B 模型**：LoRA 微调，测显存、吞吐、效果，写出"什么规模的任务值得微调"的结论；
7. **推理服务**：把任一模型封装成 C++ 服务，含动态批处理、监控、压测报告。

**每个项目都要写一份 README**：目标、数据、方法、指标、失败尝试、结论。这份文档比代码更能证明你的能力。

## 16.3 常见的学习误区

- **只收集教程不动手**：AI 的直觉来自调参时看到的反常现象，不是来自阅读；
- **一上来就学大模型**：没有传统机器学习与深度学习的基础，看 LLM 论文只能记住名词；
- **追求 SOTA 复现**：复现一篇论文的收益远低于把一个简单模型做到极致；
- **忽视工程**：真实项目的 80% 工作量在数据、部署、监控；
- **不看失败案例**：错误分析的收益通常是换模型的三倍。

## 16.4 术语表

| 术语 | 一句话解释 |
| --- | --- |
| 归纳偏置 | 模型对数据做的先验假设，决定它学得快不快 |
| 过拟合 / 欠拟合 | 记住噪声 / 连规律都没学到 |
| 正则化 | 把先验写进目标函数，限制有效容量 |
| 梯度消失 / 爆炸 | 反向传播连乘导致信号指数衰减 / 放大 |
| 残差连接 | 给梯度开一条系数为 1 的直接路径 |
| 归一化（BN/LN） | 把每层输入拉回稳定尺度 |
| 注意力 | 按相似度加权聚合其他位置的信息 |
| 位置编码 | 给注意力补上顺序信息（正弦 / RoPE） |
| 分词器 | 把文本切成子词并映射为 ID |
| 上下文窗口 | 模型一次能处理的最大 token 数 |
| 温度 / top-p | 采样时的锐化与截断参数 |
| 嵌入 | 把离散对象映射为连续向量 |
| 向量库 | 支持近似最近邻检索的索引系统 |
| RAG | 先检索资料再让模型作答 |
| 微调 | 在预训练模型上用任务数据继续训练 |
| LoRA | 用低秩增量代替全量参数更新 |
| RLHF | 用人类偏好训练奖励模型再优化策略 |
| DPO | 直接从偏好对优化策略，省掉奖励模型 |
| 量化 | 用低比特表示权重与激活 |
| KV cache | 缓存历史键值，避免重复计算 |
| 蒸馏 | 用大模型指导小模型学习 |
| 幻觉 | 生成流畅但与事实不符的内容 |
| 对齐 | 让模型行为符合人类意图与价值观 |
| 提示注入 | 外部内容里藏指令，诱导模型越权 |
| 缩放定律 | 损失随参数、数据、算力增长的幂律关系 |
| 混合专家（MoE） | 每次只激活部分子网络，扩大容量而不等比例增算力 |
| 思维链 | 让模型先写推理步骤再给答案 |
| 智能体 | 能规划、调用工具、多步执行的系统 |
| 评测污染 | 测试题目出现在训练数据里导致分数虚高 |
| 分布偏移 | 线上数据分布与训练时不同 |

## 16.5 最后一句

学 AI 最有效的路径不是"读完所有资料再动手"，而是**尽早做出一个能被别人使用的东西，然后被它的失败逼着往回补原理**。
